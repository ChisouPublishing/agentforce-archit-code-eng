# Designing Salesforce Agentforce — code (English edition)

This folder holds the code printed in *Designing Salesforce Agentforce: An Architecture Textbook*, organized by chapter. It is the English (US) localization of `codes/agentforce-archit-code/`: comments, strings, agent instructions, and test data are in English, amounts are in USD (auto-refund limit $100, test order $30), and the multilingual sample in Chapter 12 uses English (default) and Spanish.

33 files are printed in the book (Apex, Agent Script, HTTP, shell, YAML, and a project tree). An additional asynchronous class is in `support/RefundQueueable.apex`.

**Verification status: pending.** The code is deployed and verified on the English scratch org `agentforce-dev` (en_US / America/New_York / USD) with the DX project in [`../agentforce-dev/`](../agentforce-dev/). Until that run is recorded in [VALIDATION.md](../agentforce-dev/VALIDATION.md), no result in this folder is a result for the English org. The design notes in [REVIEW.md](REVIEW.md) come from the Japanese edition.

## How the code gets into the book

The English chapters (`books/agentforce-architecture-eng/chapters/*.md`) mark each printed block with a placeholder fence:

````
```
@@CODE:11_custom_agent/02_VerifyCustomerAction.apex@@
```
````

`tools/inject.py` replaces each placeholder with the content of the file, so the book always prints the org-verified code. Run it from the repository root (`makebooks/`):

```sh
python3 codes/agentforce-archit-code-eng/tools/inject.py --dry-run        # list what would change; writes nothing
python3 codes/agentforce-archit-code-eng/tools/inject.py                  # inject / refresh blocks and write manifest.json
python3 codes/agentforce-archit-code-eng/tools/inject.py --check          # exit 1 unless no placeholder is left and every block equals its file
python3 codes/agentforce-archit-code-eng/tools/inject.py --manifest-only  # rewrite manifest.json only
```

- Only the lines between the fences are replaced. The opening fence (and its language) stays as the translator wrote it.
- Blocks that were injected earlier are found again through `manifest.json` (`chapter` + `chapter_block`), so running `inject.py` after a code fix refreshes the book.
- Changed chapters are backed up to `codes/backups/inject_<timestamp>/` before they are written.
- One trailing newline at the end of a file is not part of the block.

`tools/book_blocks.py` holds the list of printed files (`FILES`, with each file's kind) and the chapter/fence parser shared by the tools. `tools/extract.py` does the reverse (book → files) for the rare case where a block was edited in the book. `tools/validate.py` checks that every block equals its file and runs a local PMD analysis.

`manifest.json` records, for each file: global block number, chapter file, block number within the chapter, line, heading, and the SHA-256 of the file. It is regenerated by `inject.py` (the hashes in the current file are those of the localized files before org verification).

## What can be checked locally

| Check | Local only? |
|---|---|
| Book blocks equal the code files | Yes (`inject.py --check`, `validate.py`) |
| Apex parsing and static rules | Yes (PMD via `validate.py`) |
| Full compilation including Salesforce types, methods, and fields | Needs a Salesforce org |
| SOQL, DML, permissions, asynchronous jobs | Needs a Salesforce org |
| Prompt Builder, Models API, Agentforce calls | Needs an org with the features and permissions set up |

Even when the Salesforce CLI runs on your Mac, `sf apex run` executes in a Salesforce org. You cannot run this code locally the way you run a Python notebook. Mocking external services does not verify Salesforce permissions or transaction behavior.

Official references: [Apex CLI](https://developer.salesforce.com/docs/platform/salesforce-cli-reference/guide/cli_reference_apex.html), [Code Analyzer](https://developer.salesforce.com/docs/platform/salesforce-code-analyzer/guide/analyze.html).

### Agent Script fragments

Many `.agent` files are fragments for explanation. To compile one, add a minimal `system`, `config`, `access`, and entry point and run `sf agent validate authoring-bundle`. Omitted actions, subagents, and flows are not filled in with mock definitions.

| [12_agent_script/01_reasoning.agent](12_agent_script/01_reasoning.agent) | The `lookup_order` action definition |
| [12_agent_script/03_system.agent](12_agent_script/03_system.agent) | The `Identity` subagent, the flows `Get_Past_Order` and `Get_Current_Order`, and an agent user in your org |

`12_agent_script/04_language.agent` declares `default_locale: "en_US"` and `additional_locales: "es"`. Whether the org accepts Spanish as an additional locale is checked in the `agentforce-dev` run.

The full form agent behind the `Confirm_Return` excerpt in Chapter 11 is [07_clt_hil/agent/Return_Desk_Form_Agent.agent](11_custom_agent/07_clt_hil/agent/Return_Desk_Form_Agent.agent).

`.apex` is the extension used to store the book's code. To deploy a class to an org, you need a `.cls` and a `.cls-meta.xml` whose names match the class name; `../agentforce-dev/tools/prepare_org_validation.py` generates them (as `AFD_*` classes) from this folder. Files that contain class definitions are not passed to `sf apex run` as anonymous Apex.

## Static analysis

Run from the repository root (`makebooks/`):

```sh
python3 codes/agentforce-archit-code-eng/tools/inject.py --check
python3 codes/agentforce-archit-code-eng/tools/validate.py
```

Requirements: Python 3, Java, the Salesforce CLI with `@salesforce/sfdx-scanner` installed, and RTK. Scanner v4 is an old version; migrate to the official Code Analyzer v5 in the future. Old rules may not recognize new API behavior, so read the results together with [ORG_REVIEW.md](../agentforce-dev/ORG_REVIEW.md).

`validate.py` reads the `.apex` files and generates `.cls` files that PMD can process in `validation/pmd-input/`. Statement fragments get a class and a method, method fragments get only a class. Undefined variables and classes are not filled in with fakes. The wrappers exist only for parsing and do not make the code runnable.

The original line number is "PMD line number − wrapper_lines". For the book, add `source_line − 1` as well. Exit code 0 from the analysis means it finished; it does not mean zero defects or a successful compile.
